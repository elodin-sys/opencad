# Smoke test campaign

Proves this machine is ready for agentic CAD work with Zoo: CLI, REST API, MCP server, Zoo Design Studio, the Zoo skill packs in `.agents/skills/backends/zoo`, and the opt-in Codex worker (GPT-6 Astra; CAD turns go to the Cursor `cad-worker` by default), all exercised against small KCL 2 parts with analytic answers.

```bash
python3 smoke/run.py                 # everything: 44 checks, ~1 min plus a few minutes for the two Codex tasks
python3 smoke/run.py --sections env,skills,cli
python3 smoke/run.py --sections codex   # only the Codex worker
python3 smoke/run.py --studio        # also opens smoke/parts/bracket in Zoo Design Studio
```

Prerequisites: `zoo` CLI logged in (`zoo auth login`), `uv`/`uvx`, Python 3, `codex` CLI logged in (`codex login`) with `model = "gpt-6-astra"` in `~/.codex/config.toml`. The MCP server reads `ZOO_API_TOKEN`; the runner takes it from the environment or from `zoo auth status -t`. Every hosted execution is billed as API usage (including the ones Codex runs itself); the count is printed at the end. The codex section consumes Codex plan usage; token counts are in the evidence.

## What runs

| Section | Ids | Exercises |
|---|---|---|
| Environment | E1-E5 | CLI version, login, token, uv, Design Studio |
| Skills (static) | S1-S4 | `scripts/check_skills.py` gates, SKILL.md discovery, cold-read token budgets, sample corpus integrity |
| CLI | C1-C9 | `zoo kcl format/lint/analyze/export/snapshot`, deterministic STEP with B-rep topology, independent STL mesh check, bracket built from skill patterns, multi-file sample |
| REST API | A1-A3 | `zoo api /user`, `/ping`, file API volume of the exported STEP |
| MCP | M1-M10 | handshake, 46 tools vs `backends/zoo/zoo-tooling/mcp.md`, format/lint/mock, error surfacing, `assert`, all 126 samples mock-executed, physical properties, docs and sample search |
| Agent loop | L1-L8 | the primer's bounded loop through MCP only: check source, execute in a session, snapshot, measure, export STEP, convert to STL, re-measure with a real density, close the session |
| Codex worker | X1-X5 | `codex` CLI, `codex doctor` (gpt-6-astra via openai, ChatGPT auth), read-only round trip at max effort, a CAD task dispatched through `.agents/skills/codex-worker/scripts/codex_exec.py` (40 x 30 x 5 mm plate with a centred 10 mm hole, written by Codex into `smoke/out/codex/plate`, measured independently with `zoo kcl analyze`), then a resumed thread that changes the hole to 12 mm |

## Parts

- `parts/coupon/main.kcl`: 60 x 40 x 4 mm plate. Volume 9600 mm3, area 5600 mm2, centre of mass (30, 20, 2).
- `parts/bracket/main.kcl`: 80 x 50 x 6 mm plate, R5 corner fillets via `getCommonEdge`, four 4.5 mm holes via `hole::holes`, an `assert` guard. Analytic volume 23489.5 mm3; the engine reports 23491.2 (+0.007%).
- `parts/broken.kcl`: `var width` misuse; must be rejected with a readable message.
- `out/codex/plate/main.kcl` (generated by Codex each run): 40 x 30 x 5 mm plate, one centred through hole. Analytic volume 5607.30 mm3 at 10 mm, 5434.51 mm3 at 12 mm.

## Findings recorded by the campaign

- `hole::` `cutAt`/`cutsAt` are in the target face's local frame: on the `END` face of an XY extrusion `[a, b]` lands at global `(b, a)`. The bracket encodes the swap and would fail if the engine changed.
- `mock_execute_kcl` cannot evaluate face-dependent std code (`hole::*`); those files need `execute_kcl`.
- 5 aquarium samples declare `kclVersion = 1.0` or none while using sketch blocks; `kcl-examples/index.md` flags them.
- The hosted engine serialises one user's requests, so checks run sequentially; parallelism only blurs timings.

Outputs land in `smoke/out/` (ignored by git); the report is `smoke/report.md`.
